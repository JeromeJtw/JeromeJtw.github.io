# 学习博客写作流程

## 一篇日志必须回答的问题

1. 今天要解决的具体问题是什么？
2. 为什么这个问题对 UE 客户端开发重要？
3. 亲手执行了哪些实验或实现？
4. 哪些结果能够证明结论？
5. 遇到了什么错误、误解或版本差异？
6. 最终形成了什么可复用认识？
7. 如果面试官追问，如何用项目证据回答？

## 推荐结构

```text
背景与目标
关键概念
实践过程
验证证据
问题与排查
我的理解
面试表达
下一步
```

## 写作步骤

1. 从 `docs/drafts/day-log-template.md` 复制一份模板。
2. 将新文件放入 `docs/daily/`，使用 `day-xx-topic.md` 命名。
3. 先填写事实和证据，再写个人理解，避免凭记忆补结论。
4. 在 `docs/daily/index.md` 中加入文章链接。
5. 本地执行 `pnpm.cmd docs:build`，确认无死链和构建错误。
6. 公开前完成敏感信息与资产许可检查。

## 公开检查

- 不包含 Token、密码、Cookie、私钥或非空 SecurityToken。
- 不包含本机用户名、无必要的绝对路径或私人文件。
- 不包含前公司内部实现、源码、截图或保密信息。
- 不直接提交大型视频和许可不明确的素材。
- 技术结论有日志、代码、Trace、截图、录像或可复现实验支撑。
- 未完成或未验证的判断明确标注状态。

## Codex 可以提供的帮助

- 根据当天事实给出选题和文章提纲；
- 提供需要回答的问题与证据清单；
- 审查概念、逻辑、敏感信息和公开风险；
- 指出缺失证据和可能被面试官追问的位置。

博客正文和最终表达由学习者本人完成。
