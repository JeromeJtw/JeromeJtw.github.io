# 学习博客写作流程

## 一篇日志必须回答的问题

1. 今天要解决的具体问题是什么？
2. 为什么这个问题值得学习或实践？
3. 亲手执行了哪些实验、实现或创作？
4. 哪些结果能够支撑结论？
5. 遇到了什么错误、误解或限制？
6. 最终形成了什么可复用认识？
7. 这篇内容与哪个知识领域、系列或项目相关？

## 推荐结构

```text
背景与目标
关键概念
实践过程
验证或作品证据
问题与排查
我的理解
对外表达或作品说明
下一步
```

不同领域可以调整结构：技术内容强调复现和验证，摄影强调拍摄参数与构图分析，文学写作强调文本、修改过程和创作复盘。

## Frontmatter

```yaml
---
title: "Day 01：开发环境与基线工程"
description: "用一句话说明本次学习解决的问题。"
date: 2026-07-14
domain: ue
type: journal
series: ue-client-roadmap
tags:
  - Unreal Engine
  - Build System
status: draft
outline: deep
---
```

## 写作步骤

1. 从 `docs/drafts/day-log-template.md` 复制一份模板，并在 `docs/drafts/` 中使用 `yyyy-mm-dd-topic.md` 命名。
2. 先填写事实和证据，再写个人理解，避免凭记忆补结论；草稿阶段不会进入网站构建产物。
3. 正文通过事实、结构和公开安全审查后，将文件移动到 `docs/journal/`。
4. 在 `docs/journal/index.md` 中加入文章链接。
5. 在所属领域首页或索引中加入该文章。
6. 本地执行 `pnpm.cmd docs:build`，确认无死链和构建错误。
7. 公开前完成敏感信息、隐私和资产许可检查。

## 公开检查

- 不包含 Token、密码、Cookie、私钥或非空 SecurityToken。
- 不包含本机用户名、无必要的绝对路径或私人文件。
- 不包含前公司内部实现、源码、截图或保密信息。
- 不直接提交大型视频、RAW 原片和许可不明确的素材。
- 技术结论有日志、代码、Trace、截图、录像或可复现实验支撑。
- 摄影和文学作品确认版权、肖像权和公开范围。
- 未完成或未验证的判断明确标注状态。

## Codex 可以提供的帮助

- 根据当天事实给出选题和文章提纲；
- 提供需要回答的问题与证据清单；
- 审查概念、逻辑、敏感信息和公开风险；
- 指出缺失证据和可能被追问的位置。

博客正文和最终表达由学习者本人完成。
